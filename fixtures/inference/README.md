# Native inference reference fixtures

These files compare the Rust implementation with the frozen llama.cpp source archive
SHA-256 `2db1e23f619fcabfd628481683c57b1e3e90db86bd045900a04b6073e1843122`.

The expected results were captured through an independently compiled C++ C-API
adapter before evaluating the Rust implementation. The adapter and original
libraries remain outside the Rust product. `oracle-provenance.json` records
the compiler, adapter/executable/library hashes, model hashes, configurations
and fixture identities.

## Included data

- `ggml-vocab-llama-spm.gguf` is the unchanged, vocabulary-only test data from
  `models/ggml-vocab-llama-spm.gguf` in the supplied archive. It has zero model
  tensors. Preserve the upstream notice in the repository's `LICENSE-UPSTREAM`.
- `llama-spm-reference.json` contains 68 Unicode, whitespace, embedded-NUL,
  special-token and empty-input cases covering both independent boolean flags.
  Expected token IDs, ordinary/special piece bytes and detokenized bytes are exact.
- `stories260k-reference.json` contains six prompts, every original prompt-token
  logit row, and sixteen greedy prediction rows per prompt. It includes 96
  predicted IDs and exact emitted bytes. Floats are serialized from original f32
  values without a lossy text rounding step.
- The two `*-requests.json` files define the exact oracle inputs.

The pretrained `stories260K.gguf` is an external test input and is not included.
Its expected SHA-256 is
`270cba1bd5109f42d03350f60406024560464db173c0e387d91f0426d3bd256d`.
The model test requires this identity before execution.

## Run the conformance checks

```text
cargo test --locked --offline -p llama-inference --test native_reference original_spm -- --nocapture
```

Set `LLAMA_TEST_MODEL` to the external model path, then explicitly execute its
ignored-by-default test:

```text
cargo test --locked --offline -p llama-inference --test native_reference trained_stories -- --ignored --nocapture
cargo run --locked --offline -p llama-server --example verify_model_server -- PATH/stories260K.gguf
```

The numerical gate was fixed before comparing Rust results:
`abs(actual-reference) <= 2e-4 + 2e-5 * abs(reference)`.
This gate applies to this model and CPU path. Tokens and text use exact equality.
An explicit 9 November 2026 Windows execution compared 62,976 logit values and
observed maximum absolute error `1.764297485e-5`, with all 96 greedy IDs and all
six complete outputs exact. The compared-row count includes the final prompt row
again as the initial greedy prediction row.

The real-model server check executes HTTP requests, SSE, replay, tokenizer
routes, a stop string crossing multiple tokens, cancellation/recovery and
concurrent sequence isolation. It also requires unsupported request options and
a missing chat template to be rejected explicitly. It is separate from ordinary
transport tests that use a clearly identified test provider.

These fixtures establish the recorded behavior for a small pretrained model
and the original 32,000-token SPM vocabulary. They do not establish all-model,
all-tokenizer, accelerator, multimodal or full application parity.

## Pretrained Q4_0 regression

The Q4_0 fixture extends the independent native comparison to the external
`stories15M-q4_0.gguf` model: 19,077,344 bytes, SHA-256
`66967fbece6dbe97886593fdbb73589584927e29119ec31f08090732d1861739`.
These model weights are not bundled.

Set `LLAMA_TEST_Q4_MODEL` to that model's path and run:

```text
cargo test --release --locked --offline -p llama-inference --test native_reference trained_stories15m -- --ignored --nocapture
```

`stories15m-q4-logits.f32le.bin` is a 2,560,000-byte expected-output data file,
containing 640,000 little-endian IEEE 754 binary32 logits. It contains no header
or executable code. The companion `stories15m-q4-metadata.json` records the
twenty full 32,000-token vocabulary rows, original prompt/token IDs, sixteen
greedy predictions, expected emitted bytes and binary identity.

The data was packed only from the independently captured original C++ oracle
JSON. Five prompt rows are followed by fifteen further greedy rows. The first
greedy row equals the final prompt row at the f32 bit level; this equality was
checked before storing the shared row once. The full original JSON hash,
original library/oracle identities, request, settings and conversion procedure
are recorded in `stories15m-q4-provenance.json`.

The optional Rust regression checks the input model and expected binary hashes,
all 640,000 logits, every greedy ID, exact actual autoregressive generated bytes,
finish reason and prompt/completion usage. It reuses the existing
`2e-4 + 2e-5 * abs(reference)` numerical budget without widening it. Bitwise
equality is reported as evidence, while the portable assertion uses the fixed
numerical tolerance to allow bounded platform math differences. The source
reference uses one CPU thread, F32 KV and disabled flash attention.

This is one trained quantized model and one prompt; it is not a completeness
claim for every quantized format, model architecture, processor or backend.
