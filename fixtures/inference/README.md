# Native inference reference fixtures

These files compare the Rust implementation with the frozen llama.cpp source archive
SHA-256 `2db1e23f619fcabfd628481683c57b1e3e90db86bd045900a04b6073e1843122`.

The expected results were captured through an independently compiled C++ C-API
adapter before evaluating the Rust implementation. The adapter and original
libraries remain outside the Rust product. `oracle-provenance.json` records
the compiler, adapter/executable/library hashes, model hashes, configurations
and fixture identities.

## Included data

- `ggml-vocab-llama-spm.gguf` is the unchanged, vocabulary-only test data from
  `models/ggml-vocab-llama-spm.gguf` in the supplied archive. It has zero model
  tensors. Preserve the upstream notice in the repository's `LICENSE-UPSTREAM`.
- `llama-spm-reference.json` contains 68 Unicode, whitespace, embedded-NUL,
  special-token and empty-input cases covering both independent boolean flags.
  Expected token IDs, ordinary/special piece bytes and detokenized bytes are exact.
- `stories260k-reference.json` contains six prompts, every original prompt-token
  logit row, and sixteen greedy prediction rows per prompt. It includes 96
  predicted IDs and exact emitted bytes. Floats are serialized from original f32
  values without a lossy text rounding step.
- The two `*-requests.json` files define the exact oracle inputs.

The pretrained `stories260K.gguf` is an external test input and is not included.
Its expected SHA-256 is
`270cba1bd5109f42d03350f60406024560464db173c0e387d91f0426d3bd256d`.
The model test requires this identity before execution.

## Run the conformance checks

```text
cargo test --locked --offline -p llama-inference --test native_reference original_spm -- --nocapture
```

Set `LLAMA_TEST_MODEL` to the external model path, then explicitly execute its
ignored-by-default test:

```text
cargo test --locked --offline -p llama-inference --test native_reference trained_stories260k -- --ignored --nocapture
cargo run --locked --offline -p llama-server --example verify_model_server -- PATH/stories260K.gguf
```

The numerical gate was fixed before comparing Rust results:
`abs(actual-reference) <= 2e-4 + 2e-5 * abs(reference)`.
This gate applies to this model and CPU path. Tokens and text use exact equality.
The initial 9 November 2026 Windows execution compared 62,976 logits with
maximum absolute error `1.764297485e-5`. Matching the source's F32-product/F64-sum
reduction now makes all those Windows logits exact; Linux records maximum error
`5.722045898e-6`. All 96 greedy IDs and six complete outputs remain exact. The compared-row count includes the final prompt row
again as the initial greedy prediction row.

The real-model server check executes HTTP requests, SSE, replay, tokenizer
routes, a stop string crossing multiple tokens, cancellation/recovery and
concurrent sequence isolation. It also requires unsupported request options and
a missing chat template to be rejected explicitly. It is separate from ordinary
transport tests that use a clearly identified test provider.

These fixtures establish the recorded behavior for a small pretrained model
and the original 32,000-token SPM vocabulary. They do not establish all-model,
all-tokenizer, accelerator, multimodal or full application parity.

## Pretrained Q4_0 regression

The Q4_0 fixture extends the independent native comparison to the external
`stories15M-q4_0.gguf` model: 19,077,344 bytes, SHA-256
`66967fbece6dbe97886593fdbb73589584927e29119ec31f08090732d1861739`.
These model weights are not bundled.

Set `LLAMA_TEST_Q4_MODEL` to that model's path and run:

```text
cargo test --release --locked --offline -p llama-inference --test native_reference trained_stories15m -- --ignored --nocapture
```

`stories15m-q4-logits.f32le.bin` is a 2,560,000-byte expected-output data file,
containing 640,000 little-endian IEEE 754 binary32 logits. It contains no header
or executable code. The companion `stories15m-q4-metadata.json` records the
twenty full 32,000-token vocabulary rows, original prompt/token IDs, sixteen
greedy predictions, expected emitted bytes and binary identity.

The data was packed only from the independently captured original C++ oracle
JSON. Five prompt rows are followed by fifteen further greedy rows. The first
greedy row equals the final prompt row at the f32 bit level; this equality was
checked before storing the shared row once. The full original JSON hash,
original library/oracle identities, request, settings and conversion procedure
are recorded in `stories15m-q4-provenance.json`.

The optional Rust regression checks the input model and expected binary hashes,
all 640,000 logits, every greedy ID, exact actual autoregressive generated bytes,
finish reason and prompt/completion usage. It reuses the existing
`2e-4 + 2e-5 * abs(reference)` numerical budget without widening it. Bitwise
equality is reported as evidence, while the portable assertion uses the fixed
numerical tolerance to allow bounded platform math differences. The source
reference uses one CPU thread, F32 KV and disabled flash attention.

This is one trained quantized model and one prompt; it is not a completeness
claim for every quantized format, model architecture, processor or backend.

## Pretrained BERT and equivalent big-endian input

`bert-bge-request.json`, `bert-bge-reference.json` and
`bert-bge-provenance.json` capture the original dense BERT encoder for three
prompts, 25 token vectors and nine pooled vectors. The 384-dimensional results
contain 13,056 unique expected floats. They include every raw token vector and
mean, first/CLS and last pooling.

| External model input | Bytes | SHA-256 | Environment variable |
| --- | ---: | --- | --- |
| BGE-small F16, little endian | 67,308,128 | `f0b2fef971e8366438bfd2d9aefea1b0115919389448806d290237f638bae999` | `LLAMA_TEST_BERT_MODEL` |
| Equivalent big-endian GGUF | 67,308,128 | `0e68255af91c707227f4840603bcbd0555054b921f757d79efdb2652ae8bb952` | `LLAMA_TEST_BERT_BE_MODEL` |

```text
cargo test --release --locked --offline -p llama-inference --test bert_reference -- --ignored --nocapture
```

The original C reader rejects the opposite-endian model. The second test
therefore checks the Rust reader against the independently captured outputs of
the equivalent little-endian model; it does not imply native big-endian support.

After matching source attention and pooling reduction, Windows compares every
value exactly. Linux maximum absolute error is `1.348853111e-4`, within the
same predeclared `2e-4 + 2e-5 * abs(reference)` limit. The initial numerical
failure, per-stage diagnosis and permanent 12-layer attention fixture are
documented under `evidence/2026-11-09/bert`.

## Missing pooling metadata

The 6,832-byte `tiny-bert-missing-pooling.gguf` is generated synthetic test data
with one small F32 BERT layer and no `bert.pooling_type` key. It contains no
pretrained weights. Its original request, native results and provenance are
recorded in `bert-defaults-*`.

An untouched native default context resolves to no pooling. The ordinary
`bert_defaults` regression checks this default, explicit None and Mean controls,
token IDs and 56 native-derived floats across three prompts. This check needs
no external model download:

```text
cargo test --locked --offline -p llama-inference --test bert_defaults
```

CI additionally supplies all six pretrained model environment variables and
runs the complete set of explicit ignored model comparisons in release mode.
Other ignored vendor/hardware tests have separate prerequisites.

## Original server embedding HTTP corpus

The embedding-http-tiny, embedding-http-coercions and embedding-http-bge
JSON/provenance pairs capture actual HTTP responses from the frozen original
C++ server. The tiny model is the existing deterministic
tiny-bert-missing-pooling.gguf; the pretrained model is the hash-pinned
little-endian BGE file above. These are reference data, not an embedded server
implementation.

The ordinary tests execute 226 tiny-model transcripts plus 30 numeric-conversion
transcripts through the Rust TCP server. The separate pretrained test executes
27 transcripts with raw/normalized vectors, all four pooling modes, batched
inputs, special tokens, usage, legacy response shapes and base64 bytes.

~~~sh
cargo test --offline --locked -p llama-server --test embedding_http
LLAMA_TEST_BERT_MODEL=/path/to/bert-bge-small-f16.gguf \
cargo test --release --offline --locked -p llama-server \
  --test embedding_http -- --ignored --nocapture
~~~

Expected vectors and wire fields come only from the original server. Its
configured alias fixture-model is mapped to the Rust provider's identifier
only when the request does not supply a string model label. Explicit labels,
indices, field structure and token counts remain exact.

Windows MSVC x64 requires exact F32 bits and base64 payloads. Portable raw BERT
comparisons keep the predeclared bound 2e-4 + 2e-5 * abs(reference). Mode 0
normalization magnifies values into the range +/-32760; its bound is propagated
from the same raw-vector bound using the formula recorded in
embedding-http-bge-provenance.json, declared before the first Rust HTTP
comparison. Direct normalization of the identical native raw vectors is also
checked independently for 4,608 outputs, with zero Windows ULP difference and
at most two portable ULPs. This separates encoder math-library differences
from normalization/serialization correctness.

The numeric-conversion corpus preserves exact i64/u64 identity, native integer
narrowing, boolean conversions, finite truncation and the lexical distinction
between JSON integer and floating token arrays. Source-undefined out-of-range
floating casts are rejected safely. Multimodal requests and reranking are not
covered by this text-only embedding corpus.

These external pretrained weights are not bundled. Each model has binary F32

## Ordinary synthetic Mamba models

The three tiny-mamba GGUF files contain deterministic synthetic F32 weights,
two width-4 layers, inner width 8, state width 3, convolution width 4 and
time-step rank 2. Tokenizer metadata comes from the declared 512-entry source
test vocabulary. No pretrained model weights are included.

The default model omits `mamba.ssm.dt_b_c_rms` and ties the output matrix to
the token embedding. The RMS variant enables that metadata flag. The untied
variant supplies a separate output matrix and an explicit false flag.
Each has an independent original-runtime fixture covering empty, ordinary
and multiple-token prompts: 18 unique rows, 9,216 logits and 12 greedy IDs.
The numerical gate `2e-6 + 2e-6 * abs(reference)` was fixed before the first
Rust evaluation of these inputs. All 27,648 Windows values are exact.

The same ordinary suite checks missing/wrong-typed/zero/overflowing dimensions,
required tensor names and shapes, decoded-weight budgets, unsupported
normalization tensors, cancellation inside recurrent updates, exact state
restoration and repeatable continuation. Those rejection tests create temporary
modified inputs; they never alter the pinned native fixtures.

~~~sh
cargo test --offline --locked -p llama-inference --test native_reference tiny_mamba -- --nocapture
cargo test --offline --locked -p llama-inference --test mamba_loader
~~~
