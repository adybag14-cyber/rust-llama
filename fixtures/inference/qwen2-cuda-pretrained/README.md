# Pretrained Qwen2 CUDA reference rows

These are outputs from the original frozen llama.cpp C API, captured before
the Rust CUDA comparison. No model weights are distributed here. The inputs
are the unchanged F16 and Q8_0 Qwen2.5-0.5B-Instruct files previously checked
against the original Hugging Face converter's complete-file output.

Each host profile and storage type has two prompts, eight greedy token IDs,
and 1,975,168 unique F32 logits (7,900,672 little-endian bytes). The duplicate
last-prompt/first-generation row is retained once; metadata records exact
row offsets, tokenizer results, generated bytes, finish state and dimensions.

`*-provenance.json` records model, reference executable/source, original JSON,
metadata and packed-row identities. MSVC uses the original Windows DLLs. GNU
uses the existing original reference executable linked to the independently
built GNU libraries, whose build-provenance identity is retained. Both use
one CPU worker, F32 KV, disabled flash attention and a 128-token context.

The fixed comparison budget is `2e-4 + 2e-5 * abs(reference)`. Generated IDs
and bytes must match exactly. The test additionally checks invalid-token and
cancellation rollback, truncate/replay and reset/replay. These measurements
cover the named model files and source profiles; full CUDA parity remains open.

Run `cargo test --release --offline --locked -p llama-cuda-runtime --test qwen
-- --ignored --nocapture --test-threads=1` with an actual NVIDIA device and
the model variables documented in `docs/CUDA_RUNTIME.md`.

The capture driver, original JSON and detailed logs remain in the external
reference workspace. The repository keeps exact losslessly packed values,
provenance and a fixture integrity declaration. The frozen source is MIT
licensed; Qwen2.5-0.5B-Instruct is external Apache-2.0 model data.
