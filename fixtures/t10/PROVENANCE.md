# T10 independent reference fixtures

The expected values in the three `*-reference.jsonl` files were emitted by native executables linked against the original uploaded source. They were not generated by the Rust implementation. `provenance.json` records source, adapter, compiler and fixture identities. The C++ adapter and reference object files remain in the isolated oracle environment, outside the Rust product and its Cargo dependency graph.

## Corpus and comparison

- `chat-reference.jsonl`: 540 exact UTF-8 transcripts covering all 54 registered native names, five message histories (including empty, Unicode, whitespace, repeated system messages and tool/function roles), and both generation-prompt settings.
- `sampling-reference.jsonl`: 16 scalar algorithms, each run for 16 consecutive apply/accept steps. Candidate IDs, selected indices and sorted state compare exactly; f32 logits/probabilities use `max(3e-6, abs(reference) * 3e-6)`. Explicit seed is 42. Stateful penalties and DRY have caller-supplied token histories.
- `grammar-reference.jsonl`: 232 full or prefix strings across six grammars, with exact original prefix/completion decisions. Unicode cases include `A£🦀界`. Two grammars are the original JSON/arithmetic examples.
- `grammars/*.gbnf`: the eight unmodified grammar input-data files copied from the frozen archive, covered by the original MIT notice in the workspace license.

The sampling adapter constructs `llama_token_data_array` from `[1, -0.5, 2.5, 0, 1.2, -2]`, invokes the named original sampler, records the surviving IDs/logits/probabilities/selected index/sorted flag, and accepts any selected token. The chat adapter enumerates `llama_chat_builtin_templates`, calls `llm_chat_template_from_str` and `llm_chat_apply_template`, and records the returned string. The grammar adapter calls `llama_grammar_init_impl`, feeds Unicode scalars via `llama_grammar_accept`, and inspects original stack viability and empty-stack completion.

Regenerating the oracle requires the frozen source and an isolated C++ build. Normal Rust compilation/tests need only the checked-in data. The root T12 evidence records the original reference build separately. Fixture passing establishes this corpus only; it does not prove full sampler/template/grammar or model/runtime parity.
