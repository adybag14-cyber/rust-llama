# Dense causal Qwen3 implementation

This is a bounded CPU implementation of the dense Qwen3 language-model graph in the frozen llama.cpp source archive. It adds Qwen3 to the Rust inference facade and strict transactional Context. It does not close the full architecture, backend, application or full-port requirements.

## Source and model identity

The source oracle is the user's frozen archive, SHA-256 `2db1e23f619fcabfd628481683c57b1e3e90db86bd045900a04b6073e1843122`. The graph follows `src/models/qwen3.cpp`, the shared `create_tensor_qkv` loading rules, and the original CPU operators. The existing upstream license and notice apply to this translation.

The pretrained reference is the official [Qwen/Qwen3-0.6B-GGUF](https://huggingface.co/Qwen/Qwen3-0.6B-GGUF/tree/23749fefcc72300e3a2ad315e1317431b06b590a) file `Qwen3-0.6B-Q8_0.gguf`, pinned to revision `23749fefcc72300e3a2ad315e1317431b06b590a`. Its 639,446,688 bytes have SHA-256 `9465e63a22add5354d9bb4b99e90117043c7124007664907259bd16d043bb031`. The exact Apache-2.0 license from that revision is preserved in `fixtures/inference/qwen3/LICENSE.Qwen3.txt`. Downloaded pretrained weights remain external to the repository.

## Graph contracts

`Qwen3Config` represents head width independently from embedding width. Query width is `heads * head_dim`; key/value width is `kv_heads * head_dim`. The model therefore supports the official configuration with embedding width 1,024, 16 query heads and head dimension 128: its query projection width is 2,048. Shapes, grouping, integer products and finite configuration values are checked before execution.

Each query and key head is normalized with its learned RMS vector before full-head NeoX RoPE. The attention output projection maps the query width back to embedding width. The graph retains the frozen RMS, matrix, attention and SiLU arithmetic profiles; it does not substitute Qwen2's configuration or omit Q/K normalization.

Separate Q/K/V projections apply each present bias independently. A fused QKV projection uses its own bias when present. When the fused bias is absent, the original graph applies separate Q/K/V biases only if all three exist. Partial bias groups in that fused case remain inactive. Tied and untied output projections are supported.

Active normalization vectors and biases require F32 storage in this CPU graph. The original GGML binary operation keeps the F32 activation as its first operand and does not support a low-precision second operand for these operations. The loader checks active descriptors before weight decoding. Inactive partial fused bias groups retain their original acceptance behavior; the loader still validates their shapes and ownership.

The loader uses the validated `GgufSet` owner, primary-shard metadata and per-shard tensor offsets. Auto-discovered and explicit split lists are covered, including a first shard containing metadata and no tensors. No metadata from later shards is merged into the primary metadata.

## State and resource behavior

The strict Context uses the actual Qwen3 KV width for growth, truncation, sequence copying and serialized state. Its model fingerprint includes the Qwen3 graph tag, head dimension, Q/K normalization vectors, biases and matrix storage identities. Checkpoints and restored states cannot silently cross different Qwen3 model identities.

Cancellation, allocation failures and nonfinite execution leave the committed batch state unchanged. The existing explicit default 1 GiB state payload/copy budget remains a per-context ledger, not a total-process memory cap. It excludes execution scratch, output buffers, allocator overhead and caller-owned serialized input.

The inference facade's default decoded-weight budget remains 2 GiB. The pinned pretrained model needs 2,384,199,680 decoded-weight bytes, so its test explicitly requests a 3 GiB budget. A normal default-budget load is required to reject it before weight decoding. Requested test context sizes are 64 for synthetic models and 128 for the pretrained model; the original runtime may pad its physical allocation.

## Independent regressions

Both expected profiles were captured through the original C/C++ library before Rust comparisons. They are selected by the independently compiled target, not by a runtime option. The compact fixtures retain exact input GGUF bytes, input hashes, original token IDs and pieces, exit status, and round-trip F32 logits. Identical rows and identical input blobs are interned only after exact byte comparison. No expected numeric value is generated by the Rust implementation.

| Corpus | Cases and checks |
| --- | --- |
| Dense graph and splits | 51 configurations: 39 admitted, 8 explicitly unsupported, 3 invalid, and 1 checked nonfinite execution. Admitted cases compare 279,552 logits and 390 greedy IDs per profile. |
| Active vector storage | 17 configurations: 12 native rejection cases, an F32 control, and 4 valid ignored partial fused-bias cases. The valid cases compare 15,360 logits and 10 greedy IDs per profile. |
| Official pretrained Q8_0 | Three prompts, 5,469,696 nonduplicated logits and 24 greedy IDs per profile. The complete tokenizer pieces, generated bytes and generation statistics are also checked. |

The tiny graph corpus covers independent attention widths, MHA/MQA/GQA, an embedding width not divisible by head count, learned Q/K norms, all separate and fused partial-bias subsets, fused own bias, tied/untied outputs, F32/F16/Q4_0/Q4_K projection cases, and implicit key/value length defaults. Q8_0 projection execution is exercised by the pretrained model.

The original Windows MSVC and Linux GNU profiles have separate expected data. The measured x86_64 targets enforce exact F32 bits, token IDs and piece bytes. Other targets retain the predeclared portable bound `2e-4 + 2e-5 * abs(reference)`; this is not evidence that unmeasured targets have been validated.

The storage rejection regression preserves the initial Rust failure: it previously admitted all 12 active low-precision vector cases that the original CPU graph rejected. The targeted descriptor check closes that discrepancy. Native process failures are converted to checked Rust errors; no original transaction-rollback behavior is inferred from a native abort.

Ordinary runtime tests additionally exercise cancellation at each boundary, multiple sequences, state reservations and copies, fork/truncate/serialization, changed-model identity rejection, late-batch nonfinite rollback and the existing allocation-fault tests with the Qwen3 model variant.

Run ordinary checks:

```sh
cargo test --offline --locked -p llama-model-runtime -p llama-inference --all-targets
cargo test --offline --locked --release -p llama-model-runtime -p llama-inference --all-targets
```

Set `LLAMA_TEST_QWEN3_MODEL` to the external pinned model and run the explicit pretrained test:

```sh
cargo test --offline --locked --release -p llama-inference --test qwen3 official_qwen3_q8_matches_original_native_profile -- --ignored --nocapture
```

The fixture test verifies the entire model hash before use. Provenance for the core and storage corpora is in `fixtures/inference/qwen3/provenance.json` and `vectors-provenance.json`.

## Explicit remaining scope

Per-layer dimension arrays, unequal key/value head lengths, partial or scaled RoPE, nonunit attention gain, noncausal attention, sliding-window attention, MoE, classifier/reranker and additional embedding projections are outside this slice and return explicit unsupported errors when encountered. Qwen3 MoE, VL, Next and other separate architectures remain separate port work.

The broader C NativeContext execution path remains Llama-only; adding a Rust inference architecture does not imply C execution parity. GPU execution and the original scheduler's full batching behavior remain separate work. Existing chat-template handling does not establish full Qwen3 thinking, tool-use or Jinja parity.

The new storage preflight is specific to the Qwen3 loader. It does not claim that every other architecture's active vector storage acceptance has been audited.
