Input contains eight complete 18-byte Q4_0 blocks, grouped as four matrix rows of 64 values. The FP16 scale bits are `3c00`, `3800`, `bc00`, `3400`, `0001`, `0400`, `c000`, `4000`. Packed byte patterns vary each nibble. Output contains 256 little-endian F32 reference values. Normal, negative, small-normal and subnormal scales are included; this is not an exhaustive format test.

The Rust test runs the generated matvec instruction tree with each of 64 basis vectors and compares all four outputs against independent reference floats. This exposes low/high nibble order, block/row addressing and scale conversion errors. Ordinary F32 numerical equality is used; signed-zero bit equality is not claimed.

## Reproduction

```bash
cargo run --offline -p llama-device-family --example record_q4_reference -- \
  /path/to/frozen/llama.cpp-master \
  /path/to/temporary/oracle-build \
  crates/device-family/fixtures
```

The recorder is Rust. It invokes `cc` and `ld` with argument arrays, compiles the supplied original `ggml-quants.c` into an isolated object, uses section garbage collection to keep the Q4_0 oracle, and loads that external oracle solely to record data. No C harness or original implementation is copied into the Rust product. Native compiler output stays in the explicitly supplied temporary directory.

Recorded with `cc (Debian 14.2.0-19) 14.2.0` and GNU ld 2.44, Linux x86-64. The original source carries the repository's MIT license; preserve the root license/attribution. Fixtures are synthetic and contain no downloaded model weights or user data.
