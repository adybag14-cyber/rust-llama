# T09 checkpoint — media preprocessing

**Status: partial implementation, compiled and executed on Linux x86-64. This is not a completed multimodal runtime.**

Baseline: uploaded `llama.cpp-master.zip`, SHA-256 `2db1e23f619fcabfd628481683c57b1e3e90db86bd045900a04b6073e1843122`. Toolchain: supplied Rust 1.99.1, `rustc 1.99.1 (58cf8f9c3 2026-10-13)`. Implementation is `crates/llama-media`; no external Cargo dependency, `unsafe` block, native codec, FFmpeg subprocess, legacy llama/ggml call, or model-weight dependency is used by it.

## Independent reference evidence

The reference programs were built separately from the new Rust source. They directly included the frozen `mtmd-image.cpp`, `mtmd-audio.cpp`, `stb_image.h` and `miniaudio.h` implementations. Linker section garbage collection discarded unrelated model code; the only shim used by the preprocessing oracle was an assertion handler that terminates on a source assertion. No reference program is linked into the Rust crate or needed to execute its tests.

The oracle's `reference-preprocessing.tsv`, `reference-codecs.tsv` and PNG `.rgb` files are committed independent expected outputs. Expected values were **not generated by the Rust implementation**. Fixture identities and origins are in `t09-fixture-manifest.tsv`; oracle compiler/driver/binary identities are in `t09-oracle.json`.

Observed selected-fixture outcomes:

- Eleven resize cases: **822 exact RGB bytes**.
- PNG corpus: **16 images, 1,039,347 exact decoded RGB bytes**, including 1,037,322 bytes from the uploaded original OCR image.
- PNM/BMP: four inputs, 72 exact decoded RGB bytes.
- PCM8/16/24/32 and float32/64 WAV: 35 float samples, exact equality.
- Normalization, FFT sizes 7/8/10/16/400, periodic windows, Slaney/HTK filters, log-mel and ISTFT: **zero observed absolute difference** on the recorded fixture values. Tests permit the declared `1e-6 + 1e-5 * |reference|` tolerance for transforms and `1e-7 + 1e-5 * |reference|` for filter weights; this is not a cross-platform bit-exactness claim.
- 31 Rust tests cover the above plus malformed inputs, every short codec-fixture prefix, PNG checksums, a bounded 2,048-input malformed DEFLATE corpus, audio shape/rate constraints, finite-value checks, FFT round-trip, streamed-state lifecycle and rejection-preserves-state checks.

These are selected behavioral checks, not complete codec coverage, fuzzing certification, a full reference test-suite run, or model-quality/performance evidence.

```sh
cargo test -p llama-media --offline --locked -- --nocapture
cargo clippy -p llama-media --offline --locked --all-targets -- -D warnings
cargo build -p llama-media --release --offline --locked
```

The worker initially used `cargo test -p llama-media --offline` in its isolated worktree before the coordinator finalized the shared lockfile. `t09-validation.txt` records actual local invocations and exit results. Integration tests obtain PNG corpus files relative to `CARGO_MANIFEST_DIR`, so the fixture tree must stay next to `crates/` in the saved workspace.

### Oracle build commands

`REFERENCE` is the extracted original archive root; `ORACLE` is an isolated directory outside the Rust product. `oracle.cpp`, `codecs.cpp` and `png.cpp` were temporary test adapters whose hashes are preserved in `t09-oracle.json`; they are **not delivered project implementations**. Re-running fixture generation requires recreating those adapters using the fixture specification below, or using an independently built equivalent original entry point.

```sh
g++ -std=c++17 -O2 -ffunction-sections -fdata-sections \
  -I"$REFERENCE" -I"$REFERENCE/include" -I"$REFERENCE/common" \
  -I"$REFERENCE/ggml/include" -I"$REFERENCE/ggml/src" \
  "$ORACLE/oracle.cpp" -Wl,--gc-sections -o "$ORACLE/oracle"
g++ -std=c++17 -O2 -ffunction-sections -fdata-sections \
  -I"$REFERENCE" "$ORACLE/codecs.cpp" -Wl,--gc-sections \
  -pthread -ldl -lm -o "$ORACLE/codecs"
g++ -std=c++17 -O2 -I"$REFERENCE" \
  "$ORACLE/png.cpp" -o "$ORACLE/png"
```

The image pattern is RGB `[(53*x+29*y+7)%256, (17*x+83*y+11)%256, (97*x+13*y+19)%256]`; each test's source/target shape, filter and padding appears in `tests/reference.rs`. Letterbox color is `[13,29,47]`. FFT/log-mel input is `(((7*i)%19)-9)/16.0f`. Filterbank settings are `N=400, mel=8, rate=16000, Slaney+area normalization` and `N=16, mel=6, rate=16000, fmin=20, fmax=7600, HTK without area normalization`. Original decoded codec outputs request RGB3 or native-rate/native-channel f32 PCM. PNG adapters write the original `stbi_load_from_memory(...,3)` output without further transformation.

## Public API and integration contracts

Use `image::decode` and `audio::decode_wav` with `DecodeLimits`. `RgbImage`, `ImageSize`, `ImageTensor`, `AudioBuffer`, `MelFilterbank`, `FftPlan` and `StreamingIstft` validate their shapes/parameters at construction. Image pixels remain interleaved RGB; spectrogram layout conversion is explicit. Source sample rate/channels stay in `AudioBuffer`, preventing an implicit resample from being mistaken for reference-compatible conversion.

`input::{InputChunk, SequenceId, Position, EmbeddingBatch, Cancellation}` are provisional Rust-owned integration seams. T01/T02/T05 must reconcile them with the central contracts when those tracks are supplied. There is no frozen C ABI, shared native-memory serialization, GGUF/model loading, tensor-backend integration or projector execution in this crate.

## Deliberate safety/lifecycle differences

- Decode resource ceilings are explicit, and malformed media returns an error. The default encoded-input ceiling is 128 MiB, decoded image ceiling 32 Mi pixels, decoded audio ceiling 32 Mi samples, and each transform allocation is capped at 256 MiB. Callers can tighten decode limits. Model-specific large-media compatibility remains a gate.
- PNG CRC/Adler, RIFF lengths, float finiteness and parameter validity are checked. Some malformed inputs accepted by the legacy decoder are intentionally rejected. The narrow BMP/PNM/WAV variant sets return explicit pending-capability errors rather than guessing.
- Odd FFT factors above 1024 and FFT lengths above 65536 are rejected to bound quadratic fallback work. Normal model FFT sizes used by the fixtures are accepted.
- ISTFT `finish()` is idempotent and subsequent frames require reset. The original emits additional zeros on repeated `flush()` calls. Empty-stream finish returns empty. Valid nonempty first-flush behavior is compared with the source; this lifecycle strengthening is explicit.
- Streaming resampler and ISTFT output allocation, shape/finite-value validation and counter-overflow checks occur before state changes. A rejected request leaves the next successful stream output unchanged. This local guarantee does not establish the separate sequence-memory transaction required from T05.

## Remaining blockers and next tasks

1. Integrate the central tensor/runtime/model/format contracts from T01/T02/T04/T05 and implement an actual image projector plus an audio encoder using real, licensed reference weights. Preprocessing results do not satisfy the embeddings gate by themselves.
2. Port model-specific image patch/position policies and audio padding/normalization/resampling, expanding the numerical corpus before declaring any of the 58 builders complete.
3. Implement or audit Rust JPEG, Adam7 PNG, remaining stb formats, MP3/FLAC/compressed WAV and filtered resampling. Pin the FFmpeg accepted container/profile matrix before replacing WebP/video decoding and soundtrack alignment.
4. Port speech/acoustic model execution and tokenizer/decoder/waveform state beyond the ISTFT primitive; test independent sequences and cancellation with the runtime.
5. Validate non-Linux targets and performance. No hardware/backend/model-quality performance claim is established by this checkpoint.
