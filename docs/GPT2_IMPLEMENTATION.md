# GPT-2 decoder implementation and evidence

This addition implements the dense causal GPT-2 graph from the frozen
`src/models/gpt2.cpp` in Rust. It makes GPT-2 available through
`llama-inference::Model`, the shared Rust generation path, and
`llama-model-runtime::Context`.

The frozen source ZIP SHA-256 is
`2db1e23f619fcabfd628481683c57b1e3e90db86bd045900a04b6073e1843122`.
The GPT-2 source file SHA-256 is
`257a04fbb14200797cbc4bb3fb26156a2d9a823df2b5c21579b6c6c291d42d6a`.
Capture commands, original executable and library hashes, input hashes, and
compiler profiles are retained in
[fixture provenance](../fixtures/inference/gpt2/provenance.json).
The validation reports and original failure records are in
[evidence/2026-11-11/gpt2](../evidence/2026-11-11/gpt2/summary.json).

## Executed graph

The Rust implementation preserves the frozen graph's operation order:

1. Look up the token embedding, or accept an explicit token embedding.
2. Add the learned position vector for the current sequence position in either case.
3. Apply affine LayerNorm, fused Q/K/V projection and its bias, then causal attention.
4. Apply the attention output projection and bias, and add the first residual.
5. Apply affine LayerNorm, FFN up projection and bias, GELU, then FFN down
   projection and bias, and add the second residual.
6. Apply final affine LayerNorm and the tied or separate output matrix, then the
   optional output bias.

Uniform grouped-query and multi-query configurations use the source's fused
Q/K/V dimensions and KV head mapping. A head width need not be even because
this graph uses learned positions rather than rotary positions. Active
normalization and bias vectors require F32 storage, matching the source CPU
operators. The model uses the existing Rust native math and packed matrix
operations; it does not link an original inference or math library.

The loader keeps the complete trained position table even when a request
selects a smaller context. The usable context is capped at the trained position
count. Required affine vectors and position tensors, exact typed metadata,
dimensions, finite values, and decoded weight budgets are checked before use.
Unconsumed model tensors cause an explicit unsupported error.

The shared context owns GPT-2 attention memory and stages changes before
commit. GPT-2 now participates in the runtime's allocation reservation/failure
suite. Additional regressions cover fork, truncate, save/restore, model
fingerprint mismatch, cancellation at multiple points, and a finite-weight
overflow that must roll back the entire multi-sequence batch. The model
fingerprint includes learned positions and affine biases.

## Independent numerical evidence

The expected data was captured by the frozen implementation before the Rust
comparison. It was not generated by the Rust implementation. Both captures use
one CPU worker, F32 KV storage, and flash attention disabled. MSVC and GNU
profiles retain their own original result bytes.

| Corpus | Coverage | Replayed rows per profile | Full logits per profile | Greedy IDs per profile |
| --- | --- | ---: | ---: | ---: |
| Synthetic original-writer GPT-2 | 14 executable variants and 6 checked boundaries | 434 | 222,208 | 168 |
| Official pretrained GPT-2 124M, F16 GGUF | Three prompts, eight generated tokens each | 33 | 1,658,481 | 24 |

Every replayed logit matched the corresponding original profile bit for bit on
both x86-64 Windows MSVC and x86-64 Linux GNU. The maximum absolute error was
zero on both hosts. Tokenization, ordinary and special token pieces,
detokenization, greedy IDs, and generated text also matched.

The 20 synthetic input cases exercise tied and separate outputs, optional
output bias, F32/F16/Q4_0/Q4_K matrix storage, GQA/MQA, one/two/three layers,
odd head widths, nondefault epsilon, and implicit KV head count. Four cases
exercise unsupported modes; two exercise missing required tensors. The
original implementation aborts on the two F16 active norm/bias variants.
Rust returns a checked unsupported error. The original accepts the noncausal
and per-layer head-array fixtures; these remain explicitly deferred in Rust.

Synthetic coverage establishes those graph/configuration boundaries. The
separate official-model replay establishes pretrained evidence. Quantized
pretrained GPT-2, other GPT-2 model sizes, GPU execution, other CPU/compiler
profiles, and long-context performance have not been established by this
corpus. The test retains a fixed portable numerical bound of
`2e-4 + 2e-5 * abs(reference)`, with an additional exact-bit requirement on the
two measured x86-64 profiles.

## Official-model provenance and converter input adaptation

The pretrained input is `openai-community/gpt2`, pinned to revision
`607a30d783dfa663caf39e06633721c8d4cfcd7e`.
The downloaded `model.safetensors` has 548,105,171 bytes and SHA-256
`248dfc3911869ec493c76e65bf2fcf7f615828b0254c12b473182f0f81d3a707`.
Pinned URLs and the remaining tokenizer/configuration inputs are recorded in
[model-origin.json](../fixtures/inference/gpt2/model-origin.json).

The frozen Python converter fails on the official checkpoint's
`h.0.attn.bias`: its GPT-2 path forwards the static causal mask to the generic
tensor mapper instead of discarding it. The failed invocation and output are
preserved in the evidence directory. The original source and downloaded
checkpoint were left unchanged.

An external derived validation input removes exactly twelve nonlearned
`h.0.attn.bias` through `h.11.attn.bias` causal mask buffers. Every retained
tensor is unchanged and individually hashed in
[static-mask-adaptation.json](../fixtures/inference/gpt2/static-mask-adaptation.json).
The frozen converter then creates the F16 GGUF used by both reference
executables and Rust. This is a disclosed validation-input adaptation, not a
claim that the frozen converter handled the unmodified official checkpoint.

The resulting GGUF has 252,470,528 bytes and SHA-256
`c7cb2936027231a4f2159264f9a635742d0d3bbbf1ddfd82074337b0d1c6e3a7`.
It remains outside Git. The repository contains independent expected logits,
not the pretrained model weights. The upstream
[Modified MIT license](../fixtures/inference/gpt2/LICENSE.GPT2.txt), including
its request to identify GPT-2-generated content, is preserved.

## Reproduction

The ordinary GPT-2 integration suite reconstructs its small GGUF inputs from
the pinned fixture data and needs no external download:

```text
cargo test --offline --locked -p llama-inference --test gpt2 -- --nocapture
cargo test --release --offline --locked -p llama-inference --test gpt2 -- --nocapture
cargo test --offline --locked -p llama-model-runtime
cargo clippy --offline --locked -p llama-inference -p llama-model-runtime --all-targets -- -D warnings
```

The real model test is deliberately ignored during ordinary tests. Set
`LLAMA_TEST_GPT2_MODEL` to the exact GGUF described above, then run:

```text
cargo test --release --offline --locked -p llama-inference --test gpt2 official_gpt2 -- --ignored --nocapture
```

The test checks the model byte count and SHA-256 before inference. On Hermes,
the retained model is
`C:\Users\adyba\rust-llama-reference\models\gpt2-124m-f16.gguf`;
the corresponding WSL path is
`/mnt/c/Users/adyba/rust-llama-reference/models/gpt2-124m-f16.gguf`.

Both measured hosts passed the four ordinary GPT-2 tests, the separate
pretrained test, the model-runtime debug suite (79 tests on Windows, 80 on GNU), formatting,
and strict Clippy. The first Windows runtime run exposed the registry smoke test's
old executable-architecture count of five; the count was updated to six and
that failure log is retained. No expected numerical result or tolerance was
changed to obtain these passes.

## Remaining boundaries

This addition supports dense, causal GPT-2 with uniform scalar head and FFN
metadata. Per-layer arrays, noncausal attention, nonstandard key/value
dimensions, pooling, sliding-window/expert modes, PRISM/NextN, and unknown
tensor paths fail explicitly. The Rust decoder's projection/output adapter
hooks are available; token and position embedding adapter targets are not
provided. The high-level complete-sequence embedding API still requires BERT.

The native C-compatible context path currently has a separate Llama execution
scope. This work does not claim GPT-2 compatibility for that context or for
GPU/device backends. It adds one independently validated architecture slice;
the full repository release gates in `docs/plan.md` remain open.
