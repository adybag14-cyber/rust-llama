# Merged workspace validation — 9 November 2026

These logs are generated by the Rust-owned `cargo xtask capture` command on
Windows with Rust 1.99.1. Each capture stores its command, exit code, elapsed
time, timeout/truncation state, and SHA-256 values for stdout and stderr.

| Capture stem | Scope |
| --- | --- |
| `source-audit` | Maintained Rust/data/config/documentation classification and offline local Cargo dependency graph. |

| `source-baseline` | The complete frozen 4,082-file source inventory: exact paths, sizes, SHA-256 values and ownership assignments. |
| `conformance-tests` | 20 unit tests and three cross-track tests, including malformed/missing/drifted fixture cases and strict cache/data audit boundaries. |
| `strict-clippy` | All targets of llama-server, llama-inference, llama-conformance and xtask with warnings denied. |

The current successful captures establish these specific host checks.
Source audit lists unsafe review candidates; those listings do not assert that
their full safety review is complete. Fixture integrity checks declared bytes;
domain tests separately establish numerical behavior. Full release completion
remains governed by the open requirements in `release/gates.tsv`.

The imported manifests used two different schemas. The validator now accepts
only their exact headers and verifies the appropriate fields without rewriting
historical provenance. New quantization, tensor and inference fixtures have
explicit declarations in `docs/integration-fixture-manifest.tsv`.
The independent Q4_0 expected-logit binary is data packed from the original
oracle output, not a downloaded model or an executable.

The source-role additions cover exact upstream/imported license and notice
paths, the single maintained CI workflow, known numerical reference data and
the four hash-pinned synthetic ELF parser fixtures. Foreign implementation
files remain rejected. Root `target` and `target-*` directories are excluded
only with Cargo's standard cache signature; arbitrary names and nested
directories are still audited.

Two initial failures are intentionally retained:

- `source-audit-before-t05-data-role` identified the imported numerical TSV at
  `crates/model-runtime/tests/data/ggml_reference.tsv`. Its exact role and
  fixture-integrity declaration were added after inspecting its provenance.
- `fixture-integrity-before-packed-matvec` detected newly created matvec
  fixtures while another worker was finishing them. Their final bytes and
  provenance were subsequently hash-pinned; coverage was not bypassed.

Model and server behavior is recorded in `../server/`; additional Linux and
root integration evidence have their own directories. The validation commands
and precise schema/audit boundaries are documented in `xtask/README.md`.
