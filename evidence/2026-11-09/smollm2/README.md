# Pretrained BPE and Q4_K_M decoder comparison

The existing dense Llama GGUF facade already delegates tokenizer metadata to
the native tokenizer crate. Adding the complete BPE profiles therefore enables
this pretrained SmolLM2 case without a loader-specific tokenizer exception.

The external SmolLM2-135M-Q4_K_M.gguf is 101,016,128 bytes with SHA-256
e3131339bf4e8065265593d4fd8f7bb7ff2d3abff1edb5618aa1197b89cad9f5.
The frozen original C API supplied three prompt traces, 34 unique full-vocabulary
rows, 1,671,168 logits and 24 greedy predictions before Rust evaluation.

Both Windows MSVC and WSL Ubuntu compare every checked logit bit exactly.
Prompt IDs, pieces in both special modes, detokenized bytes, greedy IDs,
actual generated bytes and usage also match. The portable test continues to
enforce the earlier `2e-4 + 2e-5 * abs(reference)` bound; it is not widened or
replaced by a platform-dependent expected file.

The compact binary and JSON metadata are lossless conversions of the original
capture. Identical overlapping prompt/greedy rows are stored once only after
an exact equality assertion. All input and output hashes and original library
identities are pinned in fixtures/inference/smollm2-q4-k-m-provenance.json.

The permanent ignored test is
`trained_smollm2_bpe_q4_k_full_logits_greedy_ids_and_text` and requires
LLAMA_TEST_BPE_MODEL. CI downloads the exact hash-checked input.
The final integrated Windows and Linux tests after the shared regression helper
was introduced are also recorded under ../mamba/{windows,linux}/pretrained-bpe.log.

This establishes the exercised dense Llama/BPE/Q4_K_M configuration. It does
not close remaining architecture variants, context modes, backend or
performance requirements.
