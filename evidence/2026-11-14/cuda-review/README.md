## Corrected finding: CUDA-RMS-001

Both `RmsScale` and `HeadRms` originally computed the F64 mean as `sum * (1.0 / dimension)`. The frozen source instead computes `sum / dimension` before converting to F32. The rounded reciprocal makes these expressions observably different at an admitted non-power-of-two width.

Frozen source:

- ZIP SHA-256: `2db1e23f619fcabfd628481683c57b1e3e90db86bd045900a04b6073e1843122`.
- File: `ggml/src/ggml-cpu/ops.cpp`, function `ggml_compute_forward_rms_norm_f32`.
- Line 4121: `const float mean  = sum/ne00;`.
- Line 4122 computes the F32 square root and reciprocal.
- Complete source-file SHA-256: `5283309a129fb6f135e38dde140932bff0cd527c5e166f8a733a0946c94a22a6` (430,182 bytes).

### Independent 98-element counterexample

Use one head of dimension 98, 98 F32 weights equal to one, and epsilon `1e-5f32` (bits `0x3727c5ac`). The input is:

```text
[12, 1, 1, 1, 2^-8, 2^-10, 2^-10, 2^-11, 2^-12, 2^-12]
followed by 88 zeros
```

Square each input in F32 and accumulate those squares in F64. The exact sum for this input is **147.00001752376556**.

| Quantity | Source F64 division | Previous F64 reciprocal multiplication |
| --- | --- | --- |
| F32 mean | 1.500000238418579 (`0x3fc00002`) | 1.5000001192092896 (`0x3fc00001`) |
| F32 scale | 0.8164937496185303 (`0x3f5105bc`) | 0.8164938688278198 (`0x3f5105be`) |
| First F32 output | 9.797924995422363 (`0x411cc44d`) | 9.79792594909668 (`0x411cc44e`) |

The scale differs by two representable F32 steps; the first output differs by one. The reviewer independently reproduced these values using explicit IEEE F32 roundings and F64 arithmetic in JavaScript and Python, then checked the arithmetic sequence against the frozen source. Expected values were not generated by a Rust runtime execution.

Both kernels now emit typed `Binary::Div` with the F64 dimension. The reviewed implementation locations are `ptx/decoder.rs` lines 783 and 826. The two tests named **RMS division rounding boundary** and **head RMS division rounding boundary** require exact bits. The scalar test uses the independent scale `0x3f5105bc`; the head test checks all 98 outputs.

The reviewer inspected the corrected source and exact regression definitions. The reviewer did not execute the final post-correction live CUDA matrix.

## Reviewed scope

- **Allocation and addressing:** reconciled the allocation plan with actual weight uploads, tied output reuse, optional bias buffers, workspace, fused scratch, KV storage, phase tables and activation-Q8 scratch; examined checked arithmetic and kernel byte bounds.
- **Independent Qwen3 head widths:** traced query width separately from model width through matrix views, fused slices, normalization, RoPE, attention projection and maximum activation scratch.
- **QKV bias behavior:** verified fused-bias priority, activation of separate fused-projection biases only as a complete group, inactive partial groups, and independent biases for separate projections.
- **Normalization and attention:** checked per-head indexing, shared head weights, GQA grouping, NeoX half-head pairing, phase indexing and corrected mean division.
- **Exponent and softmax arithmetic:** compared the no-FMA SSE2 constants and operation order with frozen `vec.h`, including split-scale branches, four-lane F32 sums accumulated in F64, scalar SiLU tails, F64 reciprocal rounding and visible nonfinite-score handling.
- **Typed PTX:** inspected validation, emitted instructions and interpreter behavior for the new rounding and bit-conversion operations used by scalar exponential evaluation.
- **State and regression coverage:** checked commit-after-success position semantics, cancellation boundaries, writes confined to the uncommitted KV row, reset/truncate replay checks, provenance handling and the two exact RMS regressions.

Supporting source identities, including frozen `ggml/src/ggml-cpu/vec.h` (SSE2 exponential at line 1321), `crates/quant/src/cpu_math.rs` and `crates/model-runtime/src/math.rs`, are recorded in `review.json`.

## Limits

This review covers the identified working-tree snapshot. It does not certify the final integrated commit or close any global release gate. Earlier test results reported by the integration author provided context; final post-correction GPU execution belongs to the separate validation evidence.

The inspection did not prove universal bit identity between the scalar exponential polynomial and every host `expf` implementation or every finite F32 input. Arithmetic review is scoped to the frozen scalar MSVC and no-FMA SSE2 GNU profiles used by this work.

Dense Llama, Qwen2 and Qwen3 admission and its explicit dtype/graph restrictions were in scope. Other architectures, backends, unsupported graph variants and other compiler math profiles were not certified. The reviewer made no implementation or test-source edits when producing this record.
