# Native dense Llama CUDA execution receipts

This checkpoint executes complete dense Llama graphs through Rust-authored
typed PTX on the Hermes RTX 4090. Windows MSVC and Ubuntu GNU/WSL share that
physical GPU; the NVIDIA driver is 621.01 and the compiler is Rust 1.99.1.
These are measured host/profile results, not full CUDA-backend or hardware
matrix closure. The original twenty mandatory full-port gates remain open.

Every successful replay uses the unchanged existing criterion
`abs(actual-reference) <= 2e-4 + 2e-5 * abs(reference)`. IDs and generated text
are exact. F32 uses the original matching-host C-API corpus; F16 uses one
independent original MSVC CPU capture on both hosts; Q4 uses the retained
original scalar reference. No expected model output comes from the Rust
instruction interpreter.

The new live kernel corpus has 135 analytical cases with two persistent
launches each, seven malformed-uniform guards, foreign-context/short-buffer
rejection and retained-context lifetime checks. A separate biased GQA model
compares 44 original GGML values, with maximum absolute error 1.4901161e-7.
Its requested CUDA-buffer budget accepts exactly 3,812 bytes and rejects 3,811.
Two finite-huge-weight models reject numerical failure without advancing their
prefix and recover with results identical to a clean prefix.

## Existing kernel compatibility and CLI

Fresh builds of the retained `cuda_conformance` example pass all 138 original
dispatches on each host with zero numerical error, across PTX SM60 and SM89
targets executed on the RTX 4090. They also preserve buffer padding and reject
short inputs without mutation. Receipts are under [legacy](legacy/).
A test-harness executable was not mistaken for the runnable example.

[The CLI receipts](../cuda-cli/README.md) cover 128 actual commands on Windows
release and GNU debug: 52 exact native generated-text commands, 24 stop
commands, 12 logits commands with 148,480 numerical comparisons, 38 explicit
rejections and two help commands. Device/backend statistics and requested
CUDA-buffer counts are checked. Queued failures before process launch and an
interrupted GNU attempt remain separate from successful command counts.

## Retained failures and corrections

* The first model replay accepted F32 but rejected Q8_0 matrices in the
  nominally Q4 model. The implementation gained a real Q8_0 path.
* The first quantized dot used dense F32 activations and failed with an
  approximately 0.179 logit error. That trial used a provisional 0.15 absolute
  bound and still failed. The provisional bound was removed. Device activation
  quantization and native integer-block arithmetic now reproduce all 640,000
  Q4-model logits exactly under the original tight gate.
* Independent UCRT rounding capture found that adding 0.5 before truncation
  misrounds representable values immediately below half-integer boundaries.
  Exact fractional comparison and bitwise activation tests replaced it.
* Actual GPU counterexamples showed RMS overflow and query-overflow NaNs
  being erased into finite output. Typed finite predicates now preserve
  invalid results until host rejection, retaining the committed prefix.
* A shared-generation entry-order regression returned an architecture error
  before checking immediate cancellation. Lazy CPU context creation restores
  the original ordering and zero-work short circuits.
* The first root validation driver used an incorrect package selector and
  stopped before tests. Its failed v1 report remains intact.

The first three root attempts are retained under [earlier-attempts](earlier-attempts/);
independent defect captures and focused corrections are under
[cuda-review](../cuda-review/README.md). v2 records an earlier successful
Windows debug run; final post-session-fix Windows debug evidence is the
separate final direct-binary replay above.

## Boundaries and provenance

[CUDA_RUNTIME.md](../../../docs/CUDA_RUNTIME.md) states the API, supported
matrix and graph types, requested-buffer accounting and failure semantics.
The budget is not total VRAM or process RSS. Driver/context/module overhead,
allocation granularity and retained host weights are additional. CPU and CUDA
multi-token cancellation have their documented different commit boundaries.

The [F16 fixture provenance](../../../fixtures/inference/cuda/provenance.json)
records native quantizer, original C-API producer, model, request and DLL
identities. Pretrained weights and all reference implementations remain outside
the Rust product. The GPU path has no original llama.cpp/GGML runtime dependency.
Performance, additional architectures/formats, multi-device placement, other
accelerators and the native C/HTTP GPU routes remain outside this slice.
