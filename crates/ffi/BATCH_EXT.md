# Extended C batches

The native Rust C facade implements the twelve public `llama_batch_ext_*`
builders and `llama_process` for `LLAMA_PROCESS_TYPE_DECODE` with the existing
admitted dense Llama contexts. The batch owns its token IDs, embedding values,
sequence memberships, positions and output flags. Caller embedding memory is
copied before a setter returns. Processing may use token rows, embedding rows,
mixed rows, or an embedding attached to every token.

## Frozen behavior

Builder capacity checks precede sequence validation. An invalid token or
embedding can return `-2` after appending an empty entry; later operations observe
that entry. A full batch returns `-1`, and a sequence outside the batch's captured
sequence limit returns `-3`. Duplicate sequence membership is idempotent.

Positions begin at zero in the frozen token object, even though the header calls
the initial position unset. Explicit positions remain the intended caller
contract. Output flags begin false. The embedding-output and logit-output setters
change the same flag. An embedding-enabled context requests every row regardless
of those flags.

The original standard Llama graph selects its token path when every entry has both
a token ID and an embedding. Entries of that kind cannot mix with other kinds.
Homogeneous embedding input preserves the source's append-order behavior: calling
embedding setters out of entry order also changes the row order supplied to the
graph. Mixed input instead gathers each embedding by its entry's stored offset.
The regression exercises both behaviors.

The shared native decode executor retains context cancellation, output publication,
physical cache layout, F16/F32 storage and whole-batch transaction semantics. A
failed process call retains previous output buffers and cache state. Clearing a
batch empties its owned inputs and resets the embedding width; it does not clear
the context's memory.

## Boundaries

Only contexts already admitted by `llama_init_from_model` are supported.
`LLAMA_PROCESS_TYPE_ENCODE`, MTP/LiliCorr contexts, M-RoPE position vectors and
other native architectures remain open work. Every currently admitted context
has no state-embedding input, so the state setter returns false as the original
does for that context.

The batch captures its creating context's capacity, sequence limit, vocabulary
count and input width. Processing with another context requires compatible
dimensions and sufficient limits. Cross-context mismatches that can assert or
misinterpret data in the original produce checked errors. Model/context memory
is not retained by the batch; the batch's owned builder operations do not require
foreign input storage to remain alive. The usual foreign pointer, handle and
exclusive-access contracts still apply.

Dimension arithmetic, foreign pointer alignment and storage lengths are checked.
Retained embedding storage is bounded by the existing 16,777,216-element C
facade ceiling. This is an element bound, not a total process memory limit.
Malformed booleans and overflowing descriptors produce a thread-local diagnostic.
Source process assertions and undefined foreign memory accesses are not parity
targets. As in the existing C facade, allocator aborts are not recoverable;
fallible reservations do not cover every container allocation.

## Independent corpus

The fixture inputs and original outputs were captured before the Rust
implementation from the unmodified frozen source on Windows MSVC and Linux GNU.
Both native captures use the original public C header, with dynamically loaded
libraries outside the product.

The 279 scenarios contain 395 process calls, including 386 successful decodes.
Each profile contributes 640,000 exact logit words and 86,694 exact serialized
state bytes, plus output-availability, context-limit, sequence-position, embedding,
builder-return and ABI-layout comparisons. The contexts vary flash/nonflash,
all four F16/F32 cache combinations, unified/per-sequence storage and embedding
output. Setter calls overwrite their caller buffers immediately after returning.

`fixtures/ffi/batch-ext/provenance.json` records original executable, library,
model, input and output identities. Compact references are deduplicated byte
slices; reconstructing them reproduces every original JSON value exactly.
Expectations are never generated by the Rust implementation.

Focused reproduction:

```text
cargo test --offline --locked -p llama-ffi batch_ext
cargo test --offline --locked -p llama-ffi --release batch_ext
cargo clippy --offline --locked -p llama-ffi --all-targets -- -D warnings
```

These fixtures verify the declared input domains. They do not close the full
C ABI, encoder, architecture, backend or performance release gates.
